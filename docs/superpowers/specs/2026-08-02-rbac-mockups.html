1
Levels are ordered, not arbitrary. Manage ⊃ Read ⊃ No access, left to right, so the selected column reads as a posture down the page.
2
Two groups, two vocabularies. Resources take all three levels; administration is narrower — Users has no Manage, Team has no No access.
3
Greyed cells are absent, not forbidden. Those levels don't exist in the vocabulary, so no role can ever hold them.
4
No Admin toggle anywhere. isAdmin is a hard capability, stripped from API input. That's what makes privilege escalation impossible by construction rather than by validation.
5
Footer states what can't be granted. Cheaper than a member later asking why their custom role can't invite people.

Reference

How a request resolves

Four checks, cheapest first. Everything below the middleware assumes it passed.

flowchart TD
  A[Request hits gated route] --> B{IS_LOCAL_APP_MODE?}
  B -- yes --> OK[Allow]
  B -- no --> C{role missing?}
  C -- yes --> W[Allow as Admin
+ warn log + metric]
  C -- no --> D{role.isAdmin?}
  D -- yes --> OK
  D -- no --> E{rank of held level
≥ rank required?}
  E -- yes --> OK
  E -- no --> F[403 Forbidden
required: resource + level]

The missing-role branch is a deliberate fail-open

If the migration hasn't run, users resolve to Admin rather than being locked out. Self-hosted operators often upgrade mid-incident, and losing access to your own observability tool is the worse failure. The warning log and counter are what stop it being silent.

Boundary

What these screens do not do

Source permissions are UI-level until slice B

Hiding a source removes it from these screens. It does not stop a user reaching /api/clickhouse-proxy and naming the table directly. Until the query path is gated, this model governs the interface, not the data — and the product copy should say so rather than imply isolation it can't yet deliver.

Deferred to slice C

MCP tools and External API v2 — 67 enforcement points on the Bearer-token path, untouched here.

Deferred to slice D

Per-resource rules matching by name, tag or ID. Every role here is team-wide.

Not gated inline

Controls deep inside the dashboard and search pages still submit and get a server 403. List-level actions are gated; the two 3,000-line pages are not.

Ingestion key visibility

Rotation is Admin-only, but the key stays visible to anyone with team: read.
